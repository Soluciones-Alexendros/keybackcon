# Soporte — keybackcon

### Propósito de este documento

- **Objetivos:** Orientar a quien abre un issue o pide ayuda: docs, plantillas, seguridad y contacto.
- **Estructura:** Documentación → issues → vulnerabilidades → contacto → tiempos.
- **Contenido a integrar según contexto:** Adapta URLs a este CLI/GUI HID. No copies un desk de SaaS con SLA de producto.

Antes de abrir un issue revisa estas vías.

## 1. Documentación

- [README.md](README.md) — instalación y comandos
- [ARCHITECTURE.md](ARCHITECTURE.md) — capas CLI/GUI e HID
- [CONTRIBUTING.md](CONTRIBUTING.md) — setup y flujo de PR
- [docs/runbooks/dispositivo.md](docs/runbooks/dispositivo.md) — udev, hidraw, animación
- [docs/](docs/) — protocolo, ADR, guías

## 2. Issues

Preguntas reproducibles o propuestas concretas: [Issues](https://github.com/Soluciones-Alexendros/keybackcon/issues) (plantillas en `.github/ISSUE_TEMPLATE/`).

No uses un issue en blanco: `blank_issues_enabled` está desactivado.

## 3. Vulnerabilidades

No abras issues públicos. Sigue [SECURITY.md](SECURITY.md).

## 4. Contacto

- Operaciones y seguridad: [operaciones@alexendros.dev](mailto:operaciones@alexendros.dev)

## Tiempos de respuesta esperados

- Preguntas y issues: cuando podamos, sin SLA
- Issues con etiqueta `bug`: revisión inicial en 7 días naturales
- Pull requests: primera respuesta en 7 días naturales
- Vulnerabilidades: ver `SECURITY.md`
